## Context

Один статический экран с формой, итогами и списком. Общие тесты T1–T5 одинаковы для обеих реализаций.

## Goals / Non-Goals

Цель — вести недельный список и показывать взвешенный прогресс. Хранение между запусками и сетевое приложение вне задачи.

## Decisions

- Формат задачи: `{ id, title, hours, done }`. Исходные задачи создаются при загрузке, операции возвращают обновлённый массив.
- Чистые функции в `domain.mjs` следуют общему контракту. Фильтр используется для списка, а подсчёт часов всегда получает полный массив.
- Поля валидируются при отправке. Часы принимают десятичную точку или запятую, название очищается от пробелов по краям.
- Состояние ошибки связано с полем через `aria-describedby`. При ошибке форма остаётся заполненной.
- `app.mjs` обновляет интерфейс после изменения данных или фильтра. Названия добавляются как текстовые узлы.
- Узкая раскладка использует поля в одну колонку и перенос длинных названий.

## Risks / Trade-offs

Браузеры могут блокировать импорты через file://. Исходные модули рассчитаны на статический HTTP. Для автономной проверки можно встроить те же исходники в браузерный стенд.
